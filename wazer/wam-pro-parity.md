# Current WAM Pro service parity

Swarf owns the independent Rust implementation of the observed WAM 2.4 Pro
serializer/generator boundary. OpenWAM exposes it through the explicit
`wam24_pro_presegmented` research profile in `research_gcode`, verification and
comparison operations. The historical profile remains separately selectable.

This profile reproduces a **single supplied closed path**, including the
length/corner feed arrays, modal feed suppression, repeated final endpoint,
metadata truncation, two-decimal coordinate/feed values, pierce-dependent
shutdown dwell and floored displayed job time. It does not add these corner feeds
to Swarf's generic centreline draft or its existing simulator; those remain
nominal planning models. The parsed emitted trace and the vendor displayed time
are reported separately, because their calculations differ.

The differential corpus contains eight authored paths and matching SVG artifacts:
square, rectangle, triangle, short segments, shallow turn, reversed winding,
dense short segments and fractional coordinates. Inputs include feeds from 75
to 210 mm/min and pierce times from 6 to 27 seconds. The comparison is against
**actual original JS**, including its bundled math, with zero tolerance for
coordinates, effective feeds and dwells. Metadata and ordered commands are also
compared. Original comments, decimal padding and blank lines are not byte parity.

The first wider test failed on shallow-turn feeds: Rust's binary fixed formatter
produced 42.67 for 42.675, while bundled math produced 42.68. Decimal digit
rounding now reproduces the observed half-up behavior, with regression cases
1.005, 10.125, 42.675 and 108.125. The failed original run remains private under
`wazer/private/current-pro-parity-1`; corrected evidence is recorded separately.

## Runbook

With Node and retained vendor captures available, from Reversal's root:

```sh
cargo run --locked --manifest-path crates/wam-client-inspect/Cargo.toml -- --compare-corpus wazer/acquisition.json wazer/fixtures/node-service-cases.json /tmp/wam-pro-parity
```

The new output directory retains each original execution receipt, JS response,
Rust candidate, exact comparison, and aggregate `corpus.json`. A mismatch returns
failure with its comparison retained. The runner calls Swarf rather than embedding
its algorithm. Comparison receipts bind fixture, original execution receipt,
reference/candidate bytes and Rust service source. They report controller and
machine eligibility as false. For one fixture, use `--compare-services` with its
JSON path in place of the corpus manifest.

```sh
cargo test --locked --manifest-path crates/wam-client-inspect/Cargo.toml actual_vendor_differential -- --ignored
cargo test --locked --manifest-path ../fpl/swarf/crates/swarf-waterjet/Cargo.toml
cargo test --locked --manifest-path crates/sketch-intake/Cargo.toml
```

The [retained public evidence](wam-pro-parity-demonstration.json) summarizes
actual executions without committing vendor code or generated vendor outputs.
The [original oracle runbook](wam-node-oracle.md) describes capture pinning and
service extraction. Swarf is AGPL-3.0; linking its implementation into this runner
retains those obligations for the combined executable. Vendor assets remain
separate private research inputs.

## Scope and remaining verification

These comparisons establish service behavior on explicit paths; they do not
establish WAM SVG-to-cut-file parity. The initial square adapter bypasses the
vendor's maximum-length splitting, whose original constant is **5 mm**. Long
edges in these service fixtures intentionally remain long supplied edges; they
are not claimed to be paths generated by WAM's upstream processing. Its importer,
closed-path reconstruction, offsets, lead/tab splitting, 5 mm subdivision and
tiny-hole centroid branch still require independent paired tests.

The API refuses Desktop projects for this Pro profile. The owner refuses multiple
contours, open contours, nonfinite/out-of-stock coordinates, injected labels,
feeds that round to zero and paths below the supported 5.08 mm total-length bound.
There is no fallback to historical behavior for an unsupported request. Floating
point angle thresholds and additional rounding cases remain subjects for wider
coverage, not universal equivalence claims.

Original generator agreement does not certify mechanical intent, stock geometry,
firmware dialect compatibility, kerf, hydraulics or physical duration. Installed
firmware remains unknown; hardware transfer, cuts and flashing remain disabled.
`reversal-di2` tracks this service implementation; `reversal-7dd` retains upstream
source/settings pairing and `reversal-uhn` retains broader CAM qualification.

## Verified result

All eight current-profile comparisons have zero coordinate, feed, dwell,
metadata, sequence and missing-command differences at zero tolerance. The
independent live corpus test passed, and two retained Node corpus runs produced
identical reference responses for every case. The square also matches through
OpenWAM's project-bound API with exactly equal parsed commands; its comparison
was independently rebuilt and verified. Raw G-code bytes differ in presentation.

The API test also exposed equivalent JSON numeric spelling (`108.0` versus
`108`) being rejected by raw JSON value equality. Verification now compares
numeric identity exactly, with no numeric tolerance and no lossy large-integer
conversion. Reopen returns the independently rebuilt canonical owner report,
keeping project/candidate and simulation bindings stable through a JS roundtrip.
Changed numeric values, source/operations and forged authority remain rejected.
46 OpenWAM tests, 11 Swarf tests and two ordinary inspector tests pass, alongside
the explicitly executed eight-case live differential test and strict Clippy/fmt.
